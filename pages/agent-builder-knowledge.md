## Knowledge로 활용하는 방법

이 사이트는 각 주제를 별도 URL로 분리해 Agent Builder가 필요한 문맥을 검색하기 쉽게 구성했습니다. 성과관리 Agent를 만들 때 Knowledge 소스로 GitHub Pages URL을 등록하면, 사용자의 질문에 따라 효성 인재상, KPI, 코칭, DISC 페이지가 참조 문맥으로 사용될 수 있습니다.

KPI 값이 자주 바뀌는 경우에는 [KPI Agent Knowledge]({{ '/kpi-knowledge/' | relative_url }})를 함께 Knowledge로 등록하는 것이 좋습니다. 이 페이지는 원본 엑셀 기반의 영업, 생산, 연구, 재무 KPI 예시와 산식을 정적 문서로 펼쳐 Agent가 기본값, 판정 기준, 코칭 질문을 안정적으로 참조하도록 만든 페이지입니다.

개인별 KPI 값은 웹페이지 Knowledge에 저장하지 않고, [KPI 예시 테이블]({{ '/kpi-playground/' | relative_url }})에서 원본 엑셀을 다운로드해 각 사용자가 수정한 뒤 Copilot Agent 대화에 업로드하는 방식을 권장합니다. 이렇게 하면 여러 사용자가 동시에 사용해도 서로의 KPI 값이 섞이지 않습니다.

## 권장 Agent 역할

Agent는 평가자를 대신해 최종 판단을 내리는 도구가 아니라, 평가자가 더 일관된 기준으로 자료를 정리하도록 돕는 보조자입니다. 답변은 KPI 데이터, 효성 Way, 면담 기록, DISC 커뮤니케이션 팁을 결합하되 개인정보와 민감한 인사 판단은 사용자가 최종 검토해야 합니다.

## 시스템 안내문 예시

```text
당신은 효성 성과관리 코칭 Agent입니다. 답변할 때 효성 Way의 최고, 혁신, 책임, 신뢰 관점을 활용하고, KPI 데이터와 관찰 가능한 행동 사례를 구분합니다. 평가 등급을 단정하기보다 평가자가 검토할 근거, 질문, 코칭 문장을 제안합니다.
```

## 사용자 질문 예시

* "이 KPI 결과를 바탕으로 중간 리뷰 코멘트를 작성해줘."
* "방금 업로드한 개인 KPI 엑셀을 기준으로 부서별 미달 KPI와 코칭 질문을 정리해줘."
* "신뢰 관점에서 개선 피드백을 부드럽지만 명확하게 표현해줘."
* "D형 구성원과 1:1 면담할 때 질문 순서를 제안해줘."
* "성과는 좋지만 협업 이슈가 있는 구성원에게 어떤 코칭 질문을 해야 해?"
* "평가자와 구성원이 다음 면담 전 준비해야 할 자료를 체크리스트로 만들어줘."

## 운영 주의사항

* 웹페이지 내용은 평가 참고자료이며, 회사의 공식 HR 정책과 충돌할 경우 공식 정책을 우선합니다.
* 개인정보, 민감한 평가 기록, 보상 정보는 공개 GitHub Pages에 올리지 않습니다.
* KPI 산식과 가중치는 조직별 정책에 맞게 검증한 뒤 사용합니다.
* DISC는 행동 경향 참고자료이며, 채용·승진·보상 판단의 단독 근거로 사용하지 않습니다.
